# 钱迹账单清理与导入

## 类型

无状态型。

1. Skill 只写入用户本次要求的清理结果和统计表副本，不写入调用结束后必须保留的内部状态。
2. 本次调用不读取以往调用生成的账单、结果或执行记录。
3. 单次读取量只取决于本次输入文件和目标统计表，不随使用次数增长。

## 两种任务

- **只清理**：扫描钱迹账单，确认日期范围，输出独立的 `<原文件名>_清理版.xlsx`。
- **清理并导入**：除清理版外，再把同一批记录导入用户提供的财务统计表副本中，目标页默认为「5.每日收入支出明细表」。

输入支持 UTF-8 CSV 和 XLSX。其他格式先停止并说明，不静默改变读取方式。

## 连贯交互流程

先判断用户是否已经提供统计表路径，以及是否已经明确要求导入。统计表路径本身只表示存在可用目标，不等于用户已经授权导入。

### 已提供统计表路径

1. 同时只读扫描钱迹账单和统计表结构。
2. 如果用户尚未明确要求导入，在第一次确认日期范围时一并询问：

   > 可保留日期范围为……请确认最终日期范围。清理完成后，是否直接导入至「<统计表文件名>」的「5.每日收入支出明细表」？

   接受类似 `2026-07-01 至 2026-07-31，直接导入` 或 `2026-07-01 至 2026-07-31，仅清理` 的明确回复。
3. 用户已经明确要求导入且提供路径时，只询问日期范围，不重复询问是否导入。
4. 用户同意导入后，使用一次执行完成清理版生成、统计表副本导入和回读核验。

### 未提供统计表路径

1. 先扫描账单、确认日期范围并生成清理版。
2. 清理完成后主动询问：

   > 清理版已经生成。是否继续导入财务统计表？如需导入，请提供统计表文件路径；如不需要，本次任务结束。

3. 用户提供路径后，先只读检查统计表，再执行导入。用户明确不需要或没有继续回复时，停在清理版交付状态，不搜索本机文件，也不执行导入。

### 例外与停止条件

- 用户一开始明确说「只清理，不导入」时，生成清理版后直接结束，不再询问导入。
- 用户已经明确要求导入且提供路径时，不重复确认导入意愿。
- 未取得统计表路径前不得运行导入命令。
- 用户同意导入不等于授权处理日期重叠；发现重叠后仍须另行确认 `replace` 或 `append`。
- 所有询问只补当前缺失的决定，不重复询问用户已经明确提供的信息。

## 固定清理规则

按以下顺序执行：

1. 只读扫描输入文件的字段、记录数、日期范围、「账单标记」数量和「类型」分布。
2. 报告排除标记行及非收入／支出记录后的可保留日期范围，然后按「连贯交互流程」询问日期范围，并在适用时合并询问是否直接导入。问题中给出格式示例：`2026-07-01 至 2026-07-31（包含起止日期）`。收到明确起止日期前不得继续，不自行采用全部日期或上次范围。
3. 删除「账单标记」去除首尾空白后仍有内容的整行。
4. 「类型」去除首尾空白后只保留「收入」和「支出」。
5. 只保留用户指定日期范围内的记录，包含起止日期。日期无效、起始日期晚于结束日期或范围内没有记录时停止。
6. 只保留「时间」「分类」「二级分类」「类型」「金额」「备注」「标签」。
7. 将「标签」按 `#` 分成「标签 1」「标签 2」。没有 `#` 时原内容进入「标签 1」；超过 1 个 `#` 时停止，避免丢失内容。
8. 「时间」转换为真实日期值，显示为 `yyyy-mm-dd`；金额转换为数值。
9. 按日期升序排列；同一天保持输入文件中的相对顺序。
10. 输出列固定为「时间」「分类」「二级分类」「类型」「金额」「备注」「标签 1」「标签 2」。

## 目标统计表检查

用户已经提供统计表路径时可提前只读检查；只有用户明确同意导入后才允许写入统计表副本：

1. 先以只读模式检查目标工作簿，不把测试模板或用户私人路径写入 Skill 文件。
2. 目标工作表必须存在，前 8 列依次匹配「日期」「一级分类」「二级分类」「类型」「金额」「备注」「支出类型」「支出必要性」；已知模板中的「一级分类ｼｭｯﾋﾟ」也视为合法表头。
3. 固定映射为：
   - 时间 → 日期
   - 分类 → 一级分类
   - 二级分类 → 二级分类
   - 类型 → 类型
   - 金额 → 金额
   - 备注 → 备注
   - 标签 1 → 支出类型
   - 标签 2 → 支出必要性
4. 自动识别目标页顶部连续数据区与后部保留数据区，只向两者之间已经存在且带预设格式的单元格写值；容量不足、目标行不存在或 A:H 任一目标单元格不存在时停止，不创建无格式的新行或新单元格。
5. 比较目标表现有记录和本批记录的日期衔接情况：
   - 目标表为空，或本批最早日期正好是目标表最新日期的次日：正常继续；
   - 本批最早日期晚于目标表最新日期的次日：默认停止，报告两端日期及中间相隔天数。说明日期空档不等于一定缺失账单，并询问用户是继续导入还是先补充数据；只有确认继续后才使用 `--gap-policy continue`；
   - 本批最早日期早于或等于目标表最新日期：进入历史补录或日期重叠检查。
6. 如果目标表已有记录与本次导入日期重叠，默认停止并报告重叠行数和日期范围，只询问一个会改变动作的问题：
   - `replace`：清空目标表中与本批记录日期相同的旧行，再导入本批记录；
   - `append`：保留旧行并导入本批记录，可能形成重复记录。
7. 未获得用户明确选择时不得替用户决定 `replace` 或 `append`。日期重叠检查不能当作逐笔去重；相同日期、金额和备注仍可能是两笔真实交易。
8. 本批数据早于目标表最新日期时视为历史补录，默认停止并报告本批日期范围与目标表最新日期。用户确认后使用 `--historical-policy sort`：
   - 合并保留的旧记录与本批记录；
   - 在内存中按日期升序排列；
   - 同一天先保持原有记录顺序，再保持本批记录的输入顺序；
   - 不调用 Excel 界面的排序或插入整行，而是按「选择性粘贴 → 值」的语义只替换数据区 A:H 的值，因此工作表锁定不阻止处理；
   - 不新增、删除或替换单元格的样式 ID，不改变字体、填充、边框、数字格式、对齐、行高、列宽、条件格式或数据验证；
   - 保留 `sheetProtection`、后部保留数据、其他工作表和工作簿对象；
   - 导入后回读确认日期为非降序。
9. 历史补录同时存在重叠时，必须先取得 `replace` 或 `append` 决定，再取得历史重排授权；不能用一次授权替代另一项决定。

## 文件安全

- 写入统计表必须等价于 Excel 的「选择性粘贴 → 值」：目标单元格已经存在时，只替换公式／旧值所对应的值内容和必要的数据类型标记，保留单元格样式属性及其他格式结构。
- 导入前后生成格式签名并强制比较，包括 `styles.xml`、全部单元格样式 ID、行格式属性、默认行列格式、列宽、合并单元格、条件格式、数据验证、工作表保护和绘图引用。任一项不同即删除输出并停止交付。
- 原钱迹账单始终只读。
- 原财务统计表始终只读；导入结果写入同目录下带时间戳的独立副本，除非用户另行指定输出路径。
- 不支持原地覆盖统计表。输出同名文件已存在时停止或生成新的时间戳文件，不静默覆盖。
- 导入时保留工作簿中的其他工作表、样式、数据验证、保护设置、图表、切片器和数据透视表文件；将数据透视缓存标记为打开时刷新，并要求 Excel 完整重算。
- 任一步失败时不得留下只有部分导入数据的统计表副本。

## 执行

使用仅依赖 Python 3 标准库的 [scripts/qianji_bill.py](scripts/qianji_bill.py)。所有包含空格的路径都使用 shell 引号。

先扫描钱迹账单：

```bash
python3 scripts/qianji_bill.py inspect --input '<输入路径>'
```

只读检查统计表：

```bash
python3 scripts/qianji_bill.py inspect-target \
  --target '<统计表路径>' \
  --sheet '5.每日收入支出明细表'
```

收到用户日期范围后，只清理：

```bash
python3 scripts/qianji_bill.py clean \
  --input '<输入路径>' \
  --output '<清理版路径>' \
  --start-date <YYYY-MM-DD> \
  --end-date <YYYY-MM-DD>
```

清理并导入：

```bash
python3 scripts/qianji_bill.py clean-import \
  --input '<输入路径>' \
  --clean-output '<清理版路径>' \
  --target '<原统计表路径>' \
  --target-output '<带时间戳的统计表副本路径>' \
  --start-date <YYYY-MM-DD> \
  --end-date <YYYY-MM-DD> \
  --sheet '5.每日收入支出明细表' \
  --overlap-policy stop \
  --gap-policy stop \
  --historical-policy stop
```

用户先完成清理、之后才提供统计表时，直接导入已有清理版，不重复清理：

```bash
python3 scripts/qianji_bill.py import \
  --cleaned-input '<清理版路径>' \
  --target '<原统计表路径>' \
  --target-output '<带时间戳的统计表副本路径>' \
  --sheet '5.每日收入支出明细表' \
  --overlap-policy stop \
  --gap-policy stop \
  --historical-policy stop
```

只有取得对应授权后才改变参数：日期重叠使用 `--overlap-policy replace|append`，日期空档使用 `--gap-policy continue`，历史补录重排使用 `--historical-policy sort`。

## 交付核对

脚本会回读输出并输出 JSON 统计。交付前核对：

- `sourceRows = removedMarkedRows + removedOtherTypeRows + removedOutsideDateRows + outputRows`；
- 清理版表头与固定 8 列一致，类型只含收入／支出，日期非降序，日期与金额均为数值；
- 导入行数与清理版行数一致；
- 日期空档已报告 `gapDays`，只有用户确认后才继续；
- 历史补录的 `chronologicallySorted` 为 `true`，回读日期为非降序，且工作表保护仍存在；
- `pasteValuesOnly` 与 `formattingSignaturePreserved` 均为 `true`；
- `firstWrittenRow` 至 `lastWrittenRow` 位于目标可写区；
- 统计表副本可以作为 ZIP／XLSX 完整回读，目标页导入后行数符合预期；
- 原始账单和原统计表的修改时间、大小与内容未被改动；
- 只清理时向用户给出清理版路径；导入时同时给出清理版、统计表副本路径和本次采用的重叠策略。
